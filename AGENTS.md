# Project Architecture

- Dynamic CMS-created developments render through the shared full development template; this keeps future pages consistent with the MPD development experience.
- Development-specific CMS data lives in editorial_pages.development_details JSON; this keeps the development form structured without fragmenting content across tables.
- Property public SEO text is generated only from structured property facts plus the official condominium reached by condominium_id; this prevents raw scraped labels from leaking into public copy.- Portal and main-site listings are reconciled by source_id (numeric URL tail) in src/lib/reconciliation.server.ts, shared by the daily cron route and the Admin 'Rodar agora'; external_ref paths change when purpose/neighborhood change.
- Leads CRM: all form tables feed public.leads through AFTER INSERT/UPDATE triggers (upsert_lead); forms stay unchanged and new forms only need a trigger.
- /imoveis searches in the database (search_properties RPC + property_search_facets) and loads only the current page; keep its text-matching rules identical to src/lib/property-filter-legacy.ts and verify with scripts/imoveis-parity.ts.
- Listing price formatting and comparisons share src/lib/property-listing.ts; database listing_price/listing_sale_group/listing_rent_price columns order public queries before limits, while condominium responses provide separately server-sorted purpose arrays so tab changes cannot sort only the displayed subset.
- Property card/ficha photos use card_image_url / large_image_url: pre-generated WebP via /api/public/property-thumb (scripts/generate-property-thumbs.py) or, automatically, wsrv.nl URLs set by the properties_auto_thumbs DB trigger whenever the main photo changes; the Worker cannot resize images.
- E-mails de formulário são disparados pelas server functions após gravar (dispatchLeadEmails lê o lead central); textos editáveis em email_template_settings; sends logged in email_dispatch_log.
- External property photos without a pre-generated thumbnail are resized through wsrv.nl via src/lib/img-resize.ts with onError fallback to the original; cdn.uso.com.br has no resize URLs.
- Property photo tools (admin-only) live in src/lib/property-photos.functions.ts + src/components/admin/property-photo-tools.tsx: ZIP download is built in memory with fflate (never stored); "Salvar no acervo" copies originals to the private "acervo" bucket under {code}/ and sets properties.in_acervo — the daily reconciliation never deletes bucket files, so acervo copies survive the property leaving the source site.
- Public card/page photos come from the database computed field card_image (editorial_pages, streets) and src/lib/image-fallbacks.ts never returns bundled images; missing photos render BrandPlaceholder, so photo fallback order lives in one place (SQL) and generic photos can't leak back.
- Radar questionnaire logic lives only in src/components/radar/radar-flow.tsx (page and modal variants); per-objective page copy/slugs live in src/lib/radar-pages.ts, which also feeds sitemap, mapa do site and footer.
- Installable app (PWA): vite-plugin-pwa generateSW emits /sw.js; registration only via src/lib/pwa.ts and only on SITE_HOST (never preview/iframe/dev), so stale caches can't reach the editor.
- PWA and browser icons are static files under public/icons with public/favicon.ico; keep manifest, shortcuts, head links and Workbox precache in sync so uploaded brand icons are used consistently.
- FinancingSimulator has an opt-in standalone mode for the financing page; property-detail defaults stay unchanged, and standalone submissions use the existing financing simulation-to-lead workflow to keep CRM and emails unified.
- Main-site sync uses the Tokko API: src/lib/tokko-sync.server.ts (shared by daily cron, Admin 'Rodar agora') matches by source_id = Tokko ID, falling back to unique reference code; API zeros/nulls never overwrite, so unfilled provider fields can't erase portal data.
- Property titles/H1/seo_title/WhatsApp use internal_code as 'Cód.' (URL number only as fallback) and include bedrooms but never suites; suites > bedrooms are stored/shown empty (safeSuites + apiFactPatch), so bad counts never reach public text.
- Owner-acquisition pages (/anuncie-seu-imovel, /vender-meu-imovel, /alugar-meu-imovel) reuse submitRadarLead with conversion_context captacao_venda/captacao_locacao; the leads_from_radar trigger maps that to CRM source, so no new table is needed.
- Contact page form saves to contact_messages via submitContactMessage (honeypot + signup-guard IP limit), and a trigger feeds leads with source 'contato'.
